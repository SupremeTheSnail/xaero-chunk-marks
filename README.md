Xaero 世界地图（Xaero's World Map）的客户端附属模组，给地图的右键菜单加了一条「标记区块」。
被标记的区块会在地图上染色，**只写本地文件，不发送任何数据包**，所以既不会声明（claim）区块，也不会强加载（force-load）区块。

A client-side add-on for Xaero's World Map that adds a **"mark chunk"** entry to the map's right-click menu.
Marked chunks get tinted on the map. Marks live in a local JSON file only: no packets, no claiming,
no force-loading.

- Minecraft 1.20.1 / Forge 47.x
- 依赖 Xaero's World Map 1.39 及以上（开发时对照 1.39.12 与 1.47.0 的代码）
- 纯客户端模组，服务器不需要安装，也不会因为服务器没装而报红叉
- Client-only: the server does not need it and will not show a red X

## 功能 / Features

- 在世界地图上右键区块 → 菜单里多一项 `标记区块 (x, z)`，点击后该区块整块染色。
- 按住右键拖动可以框选多个区块，菜单会变成 `标记 N 个区块`。
- 已标记的区块再次右键会显示 `取消标记`。
- 鼠标悬停在已标记区块上，会有 `■ 已标记区块 (x, z)` 的提示。
- 颜色、填充透明度、边框透明度可以在 `config/xaerochunkmark-client.toml` 里改，改完会自动重绘。
- 中英文语言文件随 jar 提供（`en_us` / `zh_cn`）。

## 数据存放

```
config/xaerochunkmark/<世界标识>-<哈希>.json
```

按「存档/服务器 + 维度」分开保存，格式是人可读的 JSON：

```json
{
  "format": 1,
  "world": "Multiplayer_play.example.com|",
  "dimensions": {
    "minecraft:overworld": [[0, 0], [0, 1], [1, 1]]
  }
}
```

删除对应文件即可清空该世界的标记；换存档、换服务器不会串数据。

## 实现思路

Xaero 的世界地图本身有一套「区块高亮」（chunk highlight）机制，Open Parties and Claims 的领地染色就是走这条路：

1. **注册 highlighter**：`xaero.map.highlight.HighlighterRegistry` 里的 highlighter 列表在
   `WorldMapSession` 构造时被 `Collections.unmodifiableList()` 封死，所以本模组在
   `ClientTickEvent` 里反射拿到 `MapProcessor#getHighlighterRegistry()`，把注册表内部的
   `highlighters` 字段换成一个新的 `ArrayList`（原有内容 + 自己的 highlighter）。
2. **染色**：`ChunkMarkHighlighter extends ChunkHighlighter`，`getColors()` 返回
   「中心 + 上/右/下/左」五个颜色，Xaero 会把它们混合到 16×16 的区块像素上；相邻区块没被标记时
   用更浓的边框色，于是多个标记区块会连成一整片带描边的区域。`coveringOutsideDiscovered = true`
   让标记在还没探索过的区域也能显示。
3. **重绘**：`calculateRegionHash()` 把「该 region 里所有标记 + 当前配色」算成一个哈希。
   标记变化后调用 `MapDimension#getHighlightHandler().clearCachedHash(...)`（顺带清一圈邻居 region，
   因为边缘区块的描边颜色取决于隔壁 region 的区块），Xaero 发现哈希变了就会重建该 region 的高亮纹理。
4. **右键菜单**：`GuiMap#getRightClickOptions()` 没有对外 API，用 Mixin 在方法返回处追加一项
   `RightClickOption`。菜单项需要「鼠标所指的区块」和「拖选范围」，这些是 `GuiMap` 的私有字段，
   用反射读取；字段名对不上时只会在日志里报错并跳过，不会崩游戏。

整个链路没有任何 `Packet`、没有 `Level#setChunkForced`、也没有和服务器交互的代码。

## 构建

需要 JDK 17（ForgeGradle 6 的 toolchain 要求）与网络（首次构建会下载 Forge/MC 依赖）。

```bash
./gradlew build
```

产物在 `build/libs/xaerochunkmark-1.0.0.jar`。

Xaero's World Map 与 XaeroLib **不随仓库分发**（Xaero 的模组不是开源的），需要自己放进 `libs/`：

```bash
unzip -p libs/xaeroworldmap-forge-1.20.1-1.47.0.jar \
      META-INF/jarjar/xaerolib-forge-1.20.1-1.7.3.jar > libs/xaerolib.jar
```

具体下载地址与 PowerShell 写法见 [libs/README.md](libs/README.md)。`build.gradle` 会把 `libs/` 下
所有 jar 作为 `compileOnly` 依赖，不会打进产物；运行时由 `mods/` 里的世界地图提供。

GitHub Actions（`.github/workflows/build.yml`）会自动完成「下载世界地图 → 抽出 XaeroLib → 构建」，
所以 CI 不需要仓库里带二进制。

> 排障：如果构建卡在 ForgeGradle 的 `AccessTransformer` 步骤并抛 `ReadOnlyFileSystemException`，
> 说明当前文件系统对 `Files.isWritable` 返回了 false（某些沙箱环境如此）。可以在 Gradle 缓存里给
> `forge-<version>-userdev.jar` 的 `config.json` 清空 `ats` 列表（并同步同名 `.md5`）来跳过 AT 步骤；
> AT 只放宽 MC 内部成员的访问修饰符，本模组只用公开 API，不受影响。

## 兼容性说明

- 目标方法 `GuiMap#getRightClickOptions()Ljava/util/ArrayList;` 在 1.39.12 与 1.47.0 上一致。
  `mixins.json` 里 `injectors.defaultRequire` 设为 `0`：如果以后 Xaero 改了方法签名，注入失败只会在日志里
  报错，菜单项不出现，不会崩游戏（`required: true` 只保证配置本身加载失败时能立刻发现）。
- 反射读取的 `GuiMap` 字段：`rightClickX`、`rightClickZ`、`rightClickDim`、`mapTileSelection`。
  缺失时同样只是禁用该菜单项，并在日志里说明原因。
- 只影响世界地图，不影响 Xaero 小地图（小地图有自己的 highlighter 注册表，本模组没有接入）。

## 已知限制

- 染色走的是 Xaero 的区块高亮混合：它保留地图原像素的透明度。所以**从未探索过、地图上完全没数据**的区块，
  标记后要等那块地图有数据（走近/加载过）才会显示颜色——这一点和领地（claims）染色完全一样。
  已经有地图数据的区块则立刻显示。
- 标记数据在 `config/` 里，不在地图存档里；清地图缓存不会丢标记，删 `config/xaerochunkmark` 才会。
